Feature / 01

Building a space for builders.

Dev Desk

DevDesk started as a way to bring the scattered tools of a coding session — notes, snippets, project links, and a running task list — into one workspace instead of a dozen browser tabs. It's built as a personal utility first: something to actually use while working, not a showcase piece.

The Idea

Most days of building software involve jumping between a notes app, a terminal, and half-remembered snippets. DevDesk asks a simple question: what if those lived in one panel, organized by project instead of by app.

The Build

Built with HTML, CSS and vanilla JavaScript first, with a Node backend added later to persist projects and notes. The interface went through several layout passes before settling on a three-pane structure: projects, notes, and an active task list.

The Experience

The result is a small, fast tool that opens instantly and holds only what's relevant to the project at hand — no dashboards, no onboarding flow, just a workspace that gets out of the way.

Field Notes

01

Why I Build

Building software is still the fastest way I've found to actually learn it — reading only gets a concept halfway there; shipping something small forces the rest.

02

Design Before Code

Sketching the interface before touching a line of code saves rework later. A rough layout on paper answers more questions than an early prototype does.

03

Learning in Public

Sharing half-finished projects instead of waiting for a polished version has been a better way to stay honest about what's actually working.

04

From Idea to Software

Most ideas fall apart at the first real constraint. Writing the smallest working version early exposes that constraint before too much time is spent.
